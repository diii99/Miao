# 西江地图重设计与实景还原步骤

日期：2026-09-08。状态：仅方案，以下实施任务均未执行。

来源 ID 对应 [证据台账](01-sources-and-visual-evidence.md)。源码分析基于本轮 `D:/Miao` 文件读取，不沿用旧工作区的地图结论。本轮没有启动应用做视觉或性能测量。

## 1. 目标与范围

目标是让用户从河谷、山坡屋顶群和真实地标关系辨认出西江，并理解“在哪里、怎样经过桥与台阶到达、哪里是文化体验”。优先获得有依据的空间关系，随后提高视觉细节。

首期详细范围建议限定于已核实的核心寨区；西门、大小北门和换乘系统以周边总览表达。边界须用底图明确，不能把所有远端节点挤进一个广场。地图应标注还原范围和资料日期。

保留项目文化旅行定位、`/map` 与 `/miniapp/map` 的入口契约、公共 Shell、底部导航和已有非遗体验。真实地标与虚拟体验建立关联，但虚拟工坊不冒充现场店址。

## 3. 重设计方向

### 3.1 先把寨子作为连续空间

- 用同一套岸线与高程控制河面、河岸道路和桥端，不分别手画互不对应的形状。
- 先建立普通住宅的成片屋顶体量，按坡面和街巷分组；地标从聚落中自然突出。
- 山体、林带、梯田与建筑密度过渡保持可辨，避免整块方形地面均匀撒房子。
- 所有北向、尺度和高差来自明确资料；没有精度依据的阶段标注“空间示意”。

### 3.2 建筑与视觉

- 依据 S04/S06 区分临坡和较平地块的吊脚楼；不要把全部房屋复制成同一尺寸的亭阁。
- 建筑先定占地、层数范围、檐口与屋脊关系，再处理木构、灰瓦、石基、走廊和使用痕迹。
- 木色、灰瓦和山林色优先从同天气实拍对照提取；雨后照片不能单独代表全年色彩。
- 日景校对材质与山坡遮挡；夜景校对层叠灯光与河面反射。特效不承担“让地形看起来真实”的任务。
- 普通住宅、店铺与公共空间应共存；节庆活动作为可切换内容层，不做成全寨永久布景。S08 提供生活与保护背景。

### 3.3 地图交互

- 总览先显示河谷与少量已核实地标；放大后显示街巷、桥号和入口，避免所有标牌同时遮住屋顶。
- POI 面板显示真实名称、资料日期、照片来源和可达方式；未定位文化体验不提供伪精确地址。
- 路线区分步行、台阶、观光车、索道；没有可靠长度和高差时不显示精确分钟数。
- 观景台提供与实拍近似的固定对照视角；保留自由漫游和拍照，但不得用随意机位冒充实地机位。
- `/miniapp/map` 保持独立嵌入能力与加载完成回调；`/map` 保留现有返回与体验弹层流程。

## 4. 实施步骤与阶段交付

### 阶段 0：冻结参照与工作区边界（P0）

1. 保存当前两个地图入口的截图、路由行为和资源清单，记录设备与日期。
2. 建立变更清单；只允许地图相关文件进入本轮实施范围。
3. 确定核心寨区详细范围、周边总览范围和目标设备。

交付：现状截图、范围说明、基准资源大小与交互清单。验收：能随时对照旧版，所有后续任务有明确输入。不要在本研究轮提前执行。

### 阶段 1：补齐底图和 POI 证据（P0，阻塞真实定位）

1. 按 S10 线索获取景区导览图，补充有授权的坐标/高程资料。
2. 明确坐标系统与轴向、单位、原点、北向；不同来源坐标不直接混用。
3. 校对西门、大小北门、观景台、博物馆、芦笙场、一号桥、四号桥等条目。
4. 对每个节点保存来源、拍摄/资料日期、位置依据和置信度。
5. 官方文字游线只能用于检查节点关系；每段道路的实际走向和交通方式另核。

交付：底图版本、坐标约定、POI 台账、未决问题清单。验收：关键节点无身份冲突；未知坐标为空，不能凭当前 `[x,y,z]` 转写成经纬度。数据不足时只推进视觉示意，不宣称实地导航。

建议 POI 文档字段：稳定 ID、显示名、原文别名、类别、真实/演绎状态、地理坐标及坐标系统、场景坐标、位置误差/精度依据、来源 ID、核验日期、关联体验 ID。字段是未来数据设计，本轮不创建数据文件。

### 阶段 2：河谷与路网灰模（P0）

1. 在统一底图上描绘寨区边界、山体、河岸、林带和田园边界。
2. 构建地形与河道；先在顶视图检查岸线，再在斜视图检查高差。
3. 逐桥接通两岸；给桥面独立可行走高度，不用河床高度代替。
4. 添加沿河道路、真实路口与山坡台阶；公共广场作为路网中的空间处理。
5. 用中性建筑盒子标出聚落密度，关闭装饰、灯光特效与人物干扰。

交付：灰模、路网拓扑、桥端与入口清单。验收：河道不穿楼、桥不沿河悬空，观景台与博物馆分开；顶视图和至少两个实拍斜视机位都能对应主要轮廓。误差阈值在取得底图精度后制定，不虚构米级指标。

### 阶段 3：普通住宅与真实地标（P1）

1. 先制作少量有实拍依据的住宅类型，按真实占地与坡向排布，允许细节复用。
2. 为每个地标建立“照片—轮廓—模型—来源”的对应表；优先观景台、博物馆、桥和芦笙场。
3. 审核现有 6 个 GLB：能证实的保留并校准；仅具文化意象的转为体验展品；不因高精细就视为真实建筑。
4. 将馆址和观景台的语义拆分；保留旧体验跳转关联，避免改 ID 后失去博物馆内容。
5. 水车古渡、乌篷船、巨大中心图腾等无定位证据的装饰，不进入已核实地标层。

交付：建筑类型表、地标对应表、模型取舍记录。验收：普通住宅形成 S04 所示的连续聚落印象，每个命名地标有来源，每个艺术补全处有记录。

### 阶段 4：步行可达性与文化体验（P1）

1. 根据已核路网建立可行走区域或路线图，区分台阶、桥面和道路。
2. 让点击行走与摇杆使用同一通行约束；不可从河床抄近路、穿房或跨过陡坡。
3. 实测观景台往返、桥两岸到达、博物馆进入和体验弹层退出。
4. 把蜡染、银饰、刺绣、长桌宴等关联到合适的文化内容入口；无真实店址时明确为虚拟体验。

交付：可达路线、异常路径记录、体验映射。验收：所有标为可达的点能沿合法路径到达，游客服务交通与步行不混画。

### 阶段 5：材质、光照与移动端分级（P2）

1. 用固定相机比较灰瓦屋顶、木墙、植被与水面比例；优先减少不符实拍的饱和色和夸张屋檐。
2. 核实同机位日夜资料后调整灯光，控制每栋房独立灯源数量。
3. 普通建筑按距离简化、复用几何与材质；地标按需加载，先显示可交互低细节层。
4. 再评估压缩、纹理尺寸与资源拆包，不通过提高全部模型精度来补空间错误。

资源现状：当前加载的是无 `.optimized` 后缀的 6 个模型，磁盘合计约 98.5 MB（十进制，约 94 MiB）；这不是实测网络传输量，纹理解码内存另计。同目录有优化版本，但本轮不切换。

建议验收目标（产品目标，尚未测试）：约定代表性手机后，连续漫游 60 秒的典型帧率至少 30 FPS；弱网冷启动尽早出现可操作低细节地图。首次可交互时间和下载预算应在阶段 0 基线测量后定数值，不能写成已达成。

### 阶段 6：证据对照与回归验收（P0–P2 收口）

1. 以全寨斜视、河岸、桥端、观景台、博物馆入口、山坡街巷六类视角制作同框对照记录。
2. 对每类说明“已还原、近似、未知”，记录资料日期；不同年份变化单列。
3. 检查 `/map`、`/miniapp/map`、加载完成、相机切换、人物移动、弹层返回和四页导航。
4. 实施有代码变更后执行 `bun run build`，再做目标设备浏览器检查；本轮不执行这些实施验收。
5. 将完成的地标证据、版本差异与仍有疑问的区域一并交付。

完成标准：空间结构可与来源核对，关键点位不混淆，路线确实可达，概念内容不冒充实拍还原，原有体验与小程序入口可用。不能仅凭模型更精细或构建通过宣布“真实还原完成”。
